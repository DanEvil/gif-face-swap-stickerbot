# Faceswap Video Sticker Bot

Telegram-бот: пользователь присылает фото лица — бот заменяет лицо на исходных
стикерах, собирает персональный видео-стикерпак (WEBM) и отдаёт ссылку.
Для доступа нужно подписаться на канал(ы) и стартовать гейт-бот @KO_Gateway_bot.
В названии стикерпака — ссылка на этого бота.

## Как работает
1. `/start` → Reply-меню: «🎭 Наши стикеры» / «🙂 Свои стикеры» / «📊 Статистика» / «🔄 Заново».
2. **Наши стикеры**: бот показывает список паков из библиотеки (или 🎲 случайный пак),
   для выбранного пака — альбом-превью из исходников, затем просит фото лица.
3. **Свои стикеры**: пользователь отправляет стикер из своего набора — бот берёт
   этот стикерпак целиком за основу (`getStickerSet`, до `MAX_STICKERS` штук), затем просит фото лица.
4. Фото → InsightFace (buffalo_l) находит лицо.
5. Каждый исходный стикер (`.webm` / `.gif` / `.webp` / `.png`): покадрово находится лицо →
   `inswapper_128` заменяет → кадры собираются в WEBM
   (VP9, yuva420p, 512×512, 30 fps, луп) — формат видео-стикеров Telegram.
6. `createNewStickerSet` с `format=video` → ссылка `t.me/addstickers/...`.

Ограничение API: у Telegram нет метода проверить фактический «старт» стороннего
бота — гейт по @KO_Gateway_bot сейчас soft-проверка (кнопка «Проверить»).
Если у KO Gateway появится API — впишите его URL в `subs.py` (`_GATEWAY_API_URL`).

⚠️ Модели InsightFace — только для некоммерческого использования (MODEL.LICENSE).

## Установка
```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
Copy-Item .env.example .env   # заполнить BOT_TOKEN от @BotFather
```
ffmpeg 9 ставится через `winget install Gyan.FFmpeg`; если пути нет — укажите `FFMPEG_PATH`.
`inswapper_128.onnx` (~554 МБ, некоммерческая лицензия) скачается сам в `~/.insightface` при первом запуске.

Ускорение: если установлен `onnxruntime-gpu` (пакет требует свой CUDA/cuDNN), InsightFace
автоматически уйдёт на GPU 4060 Ti и свап ускорится в разы. В Docker-образе (CUDA-база)
GPU-сборка ставится автоматически + `gpus: all` в compose (нужны NVIDIA‑драйверы на хосте
и GPU-поддержка WSL2 в Docker Desktop).

## Запуск
```powershell
.venv\Scripts\python bot.py
```

## Docker (VPS Linux)
Первый деплой:
```bash
git clone <HTTPS-ссылка-вашего-репозитория> faceswap-bot && cd faceswap-bot
./deploy.sh    # если .env нет — запустится интерактивная настройка (python3 setup.py)
```
Повторная настройка в любой момент: `python3 setup.py && docker compose up -d --build` или правьте .env напрямую.

Настройка спрашивает:
- ID администраторов (им подписка и запуск бота не нужны)
- требовать ли подписку; на сколько каналов; ссылки (используются все сразу, т.г. `@name` или `https://t.me/...`)
- требовать ли старт гейт-бота (@KO_Gateway_bot по умолчанию); у Telegram нет API проверить фактический запуск чужого бота — используется кнопка «Проверить» (soft-check); при наличии своего API у KO Gateway впишите URL в `subs.py` (`_GATEWAY_API_URL`)
- BOT_TOKEN (проверяется живым запросом getMe)

Обновление с GitHub:
```bash
./update.sh    # git pull + docker compose build + up -d
```
Логи: `docker compose logs -f bot`

## Команды и права
- Все основные действия — Reply-кнопками: выбор источника стикеров, статистика, рестарт.
- `/stats` (и кнопка «📊 Статистика») — только для админов: сколько запустили бота, сколько прошли гейт, сколько создано стикерпаков.
- Для админов подписка/гейт не проверяются никогда.
- Прохождение гейта фиксируется в sqlite (`data/bot.db`): при создании каждого нового стикерпака подписка на все каналы проверяется заново, а условие «старт гейт-бота» для тех, кто его уже подтвердил, опускается.

Volumes: `./stickers_src` (библиотека паков), `./data` (sqlite), `./cache`, named volume `insightface-models` (~850 МБ моделей, скачивается один раз).
Проверка пайплайна в контейнере: `docker compose run --rm bot python smoke_test.py`

## Библиотека исходных стикеров
Папка `stickers_src/`: каждая **подпапка** — отдельный пак; внутри `.webm` (лучше), `.gif`, `.png`, `.webp`.
На один стикерпак пользователя берётся до `MAX_STICKERS` штук (случайная выборка).

## Очистка исходников от водяных знаков (tools/)
Скрипты для подготовки библиотеки (используются локально, до загрузки в бота):
- `tools/qr_scan.py` — поиск QR-кодов во всех WEBM (OpenCV QRCodeDetector);
- `tools/wm_run.py` — пофайловая детекция водяных знаков: статичные по времени
  (temporal std) + контрастные (Sobel) компоненты у краёв кадра → JSON боксов;
- `tools/wm_consensus.py` — консенсус по паку + ручные боксы (`MANUAL`) → итоговый JSON;
- `tools/wm_apply.py` — батч-очистка: ffmpeg `delogo` по боксам → `Stickers_clean/`
  (без боксов файл копируется как есть);
- `tools/qr_montage.py` — контакт-листы паков для визуальной проверки до/после.

Порядок: `qr_scan` → `wm_run` → `wm_consensus` → `wm_apply` → визуальная проверка `qr_montage` → чистые паки в `stickers_src/`.

## Производительность
- Лица исходных стикеров детектируются один раз и кэшируются в `cache/src_faces/` — повторные генерации идут без детекции.
- Кадры передаются в ffmpeg напрямую (без промежуточного GIF), VP9-кодирование идёт параллельно свапу.
- На CPU (Ryzen 5 4500): ~9 с на стикер. С GPU (4060 Ti, onnxruntime-gpu): ~2 с на стикер (свап ~7 мс/кадр), пак из 10 стикеров ≈ 25–30 с.
- Одновременные генерации для нескольких пользователей: `JOBS_CONCURRENCY` (по умолчанию 2); при занятых слотах бот пишет место в очереди. Загрузка моделей защищена блокировкой (нет гонки при первых запросах), VP9-кодирование ограничено 4 потоками на стикер, чтобы несколько джобов не душили друг друга.
